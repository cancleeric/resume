04 · Agent 失控實戰

治理不能只靠 Prompt，防線必須落在 Runtime

  • Tool loop：同工具、同參數反覆呼叫，卻沒有狀態進展。
  • Polling loop：輪詢永遠不變的外部狀態，Token 持續空燒。
  • Ping-pong：兩個工具交替呼叫，表面有動作、實際沒有結果。
  • Ghost agents：測試未隔離，20 多個 Agent 同時搶連線。
  • 資源死循環：殘骸容器 exit 1 後重啟，獨佔 CPU。
Sliding window
repeat / no-progress / ping-pong

WARNING → 抑制與告警
CRITICAL → 阻斷當輪
CIRCUIT BREAKER → 全域熔斷

token / turns / time / tool budget
forced teardown · restart: no
tenant isolation · RestartCount monitor

設計原則：先抑制、累積證據再升級；既擋住 runaway token，也不誤殺正常重試。

08 · 到職後 90 天

先建立基準線，再用一個試點證明價值

前 30 天｜盤點

盤點團隊、產品、模型、資料與部署流程；找出最昂貴、最慢、風險最高的環節；建立 AI 工程與治理基準線。

31–60 天｜試點

選擇高價值、可控範圍的場景；建立 Agent Runtime、Guardrail 與觀測指標；串接測試、PR、CI/CD。

61–90 天｜擴大

驗證交付時間、品質與成本改善；沉澱可重用平台及團隊規範；以數據決定下一階段擴大範圍。

可量化可回滾可重用可稽核
